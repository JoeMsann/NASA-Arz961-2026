# Flame in Freefall

NASA Space Apps 2026 entry: a dashboard that summarizes, ranks and interprets NASA microgravity combustion investigations (the PSI database) for spacecraft fire safety. The challenge text is in `docs/challenge.md`; `README.md` is the project overview. Setup, feature status and model scores are in `setup.md`.

Four people work in this repo, each with their own Claude session. The rules below exist so those sessions do not collide.

## Layout

| Path | What it is |
| --- | --- |
| `data/raw/` | Source CSVs. Never edit by hand |
| `data/catalog.json` | One hand-written entry per investigation |
| `data/environments.json` | Habitat presets (oxygen, pressure, gravity) |
| `data/build/` | Generated by the pipeline and committed. Never edit by hand |
| `pipeline/build.py` | Builds the unified table and trains the models. One mapper function per source file |
| `services/ml/` | FastAPI: table, navigator, compare, predictor (port 8001) |
| `services/agent/` | FastAPI + LangGraph: Ask PSI chat and evidence search (port 8002) |
| `services/mcp/` | MCP server for chatbots (port 8003, endpoint `/mcp`). Forwards to `ml` and `agent`; holds no data |
| `web/` | Next.js 15 interface (port 3000). Reaches the services through `/api/svc/<svc>/...` |
| `docs/` | One page per feature |

## Commands

```bash
docker compose up --build                      # everything, http://localhost:3000
python pipeline/build.py                       # rebuild data/build/
cd services/ml && uvicorn app:app --port 8001
cd services/agent && uvicorn app:app --port 8002
cd services/agent && python test_graph.py      # offline agent test, needs no API key
cd services/mcp && uvicorn app:app --port 8003
cd services/mcp && python test_mcp.py          # needs ml, agent and mcp running
cd web && npm run dev
cd web && npx tsc --noEmit                     # type-check
```

Python 3.10 or newer. The Groq key goes in `.env` (see `.env.example`). Never commit `.env`.

## Data rules

These matter more than code style. Judges will check the numbers.

- Never invent a data value. If a source does not record something, leave it null.
- Every row carries `provenance`. A value added during cleaning is named in the row's `assumed` column.
- `kind='planned'` rows have no result. `kind='threshold_1g'` rows are ground tests, and their `o2_pct` is the limiting oxygen level found, not a test condition. Do not mix either with flown tests in a chart, count or model without saying so.
- Catalog text that did not come from a NASA table must say where it came from in `details_basis`.
- The language model may propose column mappings or wording. It never writes data values, and its output is reviewed before it loads (`"approved": true` in `data/mappings/`).
- State extrapolation plainly in the interface. The predictor covers heptane and methanol droplets in microgravity only.

## Working together

- One feature per branch, one owner per feature, one pull request each. Do not push to `main`.
- Before starting, check the feature table in `setup.md` and the open pull requests, so two people do not build the same thing.
- A feature bigger than a couple of hours gets a short page in `docs/` first: what it does, which files it touches, how to check it.
- `data/build/` is generated, so two branches that rebuild will conflict on it. Do not resolve those conflicts by hand: merge `main` into your branch, run `python pipeline/build.py`, and commit the result.
- Rebuild after any change to `data/raw/`, `data/catalog.json`, `data/mappings/` or `pipeline/build.py`, and commit `data/build/` in the same pull request.
- `data/build/report.json` and `models.json` shift with the installed scikit-learn version. If you did not change the model code, do not commit changes to them.
- Stage files by name. Do not commit editor folders, lock files outside `web/`, or local dependency tweaks.

## Before opening a pull request

- `python pipeline/build.py` runs clean if you touched data or the pipeline.
- `python services/agent/test_graph.py` passes.
- `npx tsc --noEmit` in `web/` is clean if you touched the interface.
- You opened the changed tab in the browser and it works.
- The pull request says what was not tested.

## Conventions

- Backend: plain FastAPI functions in one `app.py` per service. Compute from `data/build/`; do not read `data/raw/` at request time.
- Frontend: one component per tab in `web/components/`, registered in `TABS` in `web/app/page.tsx`. Styles go in `web/app/globals.css` using the existing variables and classes (`card`, `grid`, `note`, `tag`).
- Interface text is plain language for students and engineers: say what the data shows and what it does not.
- This is a research aid. Nothing in it is flight-safety guidance or material approval, and the interface must not read as if it were.
- AI assistance is declared in the Space Apps submission.
